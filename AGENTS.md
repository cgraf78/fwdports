# AGENTS.md

## About

`fwdports` is a Bash 3.2-compatible CLI (`bin/fwdports`) that keeps declared
port forwards running in one private tmux session. Its modules live in
`lib/fwdports/`; `lib/fwdports/README.md` gives per-module ownership, and
`session-enumerator.py` is the macOS-only Python helper. Configuration is
parsed as records and never evaluated as shell.

## Layout

- `bin/fwdports`: the command.
- `lib/fwdports/`: runtime modules (implementation details, not a sourced API).
- `docs/`: `design.md` (grammar and lifecycle contract), `drivers.md`
  (executable driver protocol), `security.md` (ownership and cleanup rules).
- `examples/`: `tunnels.conf` and `drivers.d/`, read directly by
  `test/examples-test`, so keep them valid.
- `support/`: `install-checkout.sh` (installer delegate) and
  `verify-stock-et-contract.sh` (CI's real-ET gate).
- `test/`: `run`, one `*-test` suite per area, and `lib/test.sh` (harness).
  See `test/README.md`.

## Invariants

- Fail closed on unknown or incomplete ownership evidence. Never kill by name,
  port, or stale PID (`docs/security.md`).
- Claim numeric version minimums only when CI exercises them.
- External drivers stay behind the process-based protocol in `docs/drivers.md`.

## Testing

- Local and CI: `bash test/run`. It runs every executable `test/*-test`
  sequentially; never parallelize them, because suites own tmux sockets,
  process groups, and timing.
- Single case: `bash test/<suite>-test <case>`. An unknown case fails.
- `test/session-enumerator-test.py` runs from `test/process-tree-test`, not
  from the `test/run` glob.
- `test/run` never runs ShellCheck; lint is CI-only (see below).
- Stock Bash 3.2 (macOS): put a `bash` symlink to `/bin/bash` first on PATH,
  run `PREFIX=$tmp /bin/bash install.sh`, then `/bin/bash test/<suite>-test`
  for autossh-driver, builtin-runner, cli, config, driver-api, et-driver,
  ettun-driver, examples, install, portability, and ssh-driver, then
  `/bin/bash test/controller-test no-pane-stop`. New suites in that list must
  stay Bash 3.2-clean; an empty array under `nounset` counts as unbound.
- Real ET (CI only): `bash support/verify-stock-et-contract.sh <absolute et>`
  against the checksummed upstream ET 7.0.0 arm64 `.deb`.

## Test isolation

- Use only the harness's tmux wrapper: `-S <suite-root>/...`, `-f /dev/null`,
  `TMUX=''`, `TMUX_PANE=''`. Never touch the default tmux server.
- Stop servers with `fwdports stop` or `kill_test_server`. The harness fails a
  case that leaks a server and sweeps again on exit.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale
  rows; local `test/run` does not detect this. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`.
- `install.sh` is generated by cgraf78/actions checkout-installer and
  byte-checked by `actions-sync`. Edit `scripts/checkout-installer.conf` or
  `support/install-checkout.sh`, then run `consumer-ci/sync.sh <this checkout>`
  from cgraf78/actions at the locked SHA.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh`.
- Workflow-pinning tests: `test/portability-test` pins `test.yml` text (the
  `macos-bash32` job and `needs: [shell, macos-bash32, stock-et-contract]`)
  and the retry trigger; `test/license-test` pins the LICENSE text. Edit them
  together with the files they check.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename it.
- Changes to ET argv must pass the stock-ET gate, whose contract ettun shares.
